Beyond the goals · Impact story

Retry Reaches Every Mio Voice Account

Problem

  • A lead who did not pick up on the first call was never tried again, so only 38.6% of leads dialled were connected
  • Retry could not be used inside automations until each Mio Voice account was enabled on automation

What was done

  • Released Call Retry on 13 Jul 2026 and enabled every Mio Voice account on automation
  • For accounts that already ran automations before Retry: with the Ops team, duplicate draft automations with Retry on are created, and CS is mailed to switch to them
Outcome
+11.9%
connect rate, from 38.6% on the first call to 50.5% with retry, across 1.9M unique leads dialled. About 232K leads were reached only because of a retry.

Reach

  • 100% of Mio Voice accounts can use Retry in automation
  • 66 of 80 institutes (83%) and 959 of 1,805 campaigns (53%) are on retry so far

Adoption · Impact story

Every Mio Voice Account Now Has Call Filters and Call Records

Problem

  • A Mio call left only a one-line note on the lead's Timeline, so teams could read it but could not filter or report on how calls went

What was done

  • Centralized call logging: every Mio call is saved automatically as its own record on the lead, as an activity card on the Timeline and under Dynamic Activity
  • Each record holds call status, call type, AI agent, start time, duration and, for connected calls, the recording, transcript and summary
  • Enhanced Lead Manager filters: call details can be used in Advanced Filters, with Call Status, Call Type and Call Ended By as dropdowns
  • Switched the release on for the remaining accounts, with a guide for CS, Sales and Ops
100%
of Mio Voice accounts now have the enhanced filters and centralized call logging. The accounts that were still waiting to be migrated are done.

What teams can now do

  • Build lead lists by how the last AI call went: busy, not answered or connected
  • Filter by AI agent, inbound or outbound, and call date or duration
  • Report on and export the calls from Dynamic Activity

Beyond the goals · Impact story

Sharper Qualification and Goal Tracking

Problem

  • The model in use (GPT-4.1 mini) was degrading in quality
  • Wrong lead qualification became the biggest new ticket theme in Q2 (10 tasks, none in Q1)

What was done

  • Moved to GPT-5 mini at the same call cost (agreed with the vendor)
  • With Ops, set up a new way of building the extraction (decides if a lead is qualified and if the goal was achieved), showing goal achieved call by call
  • Since 23 Sep 2026, every new agent is built this way
  • Agents built before 23 Sep that still have call volume move to the tightened extraction on priority. Product team migrated Parikshe, Atmia Education, DY Patil Deemed to be University and Birla Global University; Ops is migrating the rest
Outcome so far
~12
new agents built on the new extraction since 23 Sep 2026
4
existing clients migrated by the product team
The rest of the agents with call volume are being migrated by Ops on priority, due by the week of 12 Oct. All run on GPT-5 mini at the same call cost.

The new extraction approach

  • Built from the client's RGS: qualification rules come from the client's own requirements and expectations
  • Matched to the agent's main prompt: same questions, same eligibility rules, so the result does justice to the conversation
  • Client approves it before the agent goes live
  • Monitored after go-live for wrong qualification

IssueWhat went wrongWhat was done
Lead fields not updatingBolna sent the pingback with the extraction and it was processed, but the lead-field update was not applied.Added logs to trace it, and ran a query to update the fields for the affected clients (Graphic Era, IIMT Group of Colleges).
"New key" error in Communication PerformanceBolna returned "wrong bearer token / agent does not exist". Deleting a user on Bolna moves all their agents and sub-accounts to someone else, and the bearer tokens change. Only "new key" was printed, so the real error was never seen.The exact error from Bolna is now read and logged, and these cases are handled, so the cause is visible next time.
